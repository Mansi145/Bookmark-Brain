# Deploy

**Being deployed (Phase 8, 2026-11-04).** Update this with what actually happened.

## How it fits together
```
Browser ──> https://<app>.vercel.app          (React app, Vercel)
              └─ /api/…  ── Vercel forwards ──> https://bookmark-brain-api.onrender.com (FastAPI, Render)
                                                   └─> Neon Postgres (+ pgvector)
Extension ──(token)──> https://bookmark-brain-api.onrender.com directly
```
**The browser only ever talks to the Vercel address** (owner, 2026-11-04): `frontend/vercel.json`
forwards `/api/…` to Render, so the session cookie is first-party (`SameSite=Lax; Secure`) and
works in every browser. Calling Render directly would make it a third-party cookie, which Safari
blocks. The frontend's production build calls `/api/…` on its own address (`api/client.ts`). The
extension uses its token, not a cookie, so it calls Render directly.

## Neon (database)
**Done (2026-11-05):** project `bookmark-brain` in the owner's org, region AWS Asia Pacific
(Singapore), so Render is in Singapore too (`render.yaml`). Postgres 18 with pgvector 0.8; migrated
to 0013. It was created with the Neon CLI (`neon init`), which wrote the project link to `.neon`
and the addresses to the repo root's `.env.local` (both git-ignored): `DATABASE_URL_UNPOOLED` is
the direct one to use. Local dev and tests still use docker-compose (Postgres 16).

1. Create a project (free plan). pgvector: the first migration runs `CREATE EXTENSION vector`.
2. Copy the connection string **as Neon shows it** (`postgresql://…?sslmode=require&channel_binding=require`);
   `config.py` turns it into an asyncpg URL. Use the **direct** (non-pooled) one for both the app and
   migrations: asyncpg's prepared statements don't work through the pooler, and one small app needs
   few connections.
3. Run migrations from your machine **before** deploying code that needs them:
   `DATABASE_URL='<neon url>' uv run alembic upgrade head` (keep the URL out of shell history and chat).
   From `backend/`, without the URL appearing anywhere:
   `DATABASE_URL="$(grep '^DATABASE_URL_UNPOOLED=' ../.env.local | cut -d= -f2- | tr -d '"')" uv run alembic upgrade head`
4. Free compute hours count only while the database is awake, and it suspends after 5 idle minutes.
   The worker sleeps up to `IDLE_SECONDS` (30 min) when there's nothing to do, waking at once when
   the app queues a job (`worker.wake_on_commit`), so the database can suspend. `/health` doesn't
   touch the database, so the keep-warm ping doesn't wake it.

## Render (backend)
- `render.yaml` (a Blueprint) describes the service: New → Blueprint → this repo. Free plan, root
  `backend/`, branch `development` for now (`main` from the next release), build
  `pip install uv && uv sync --frozen --no-dev`, start `uv run --no-dev uvicorn app.main:app …`,
  health check `/health`. `JWT_SECRET` is generated by Render.
- Paste the `sync: false` settings in the dashboard: `DATABASE_URL`, `FRONTEND_ORIGIN` and
  `API_ORIGIN` (**both the Vercel address**: the browser reaches the API through it),
  `GOOGLE_CLIENT_ID`, `GOOGLE_API_KEY`, optional fallback keys, optional `RESEND_API_KEY` +
  `MAINTAINER_EMAIL`.
- GitHub sign-in needs **its own production OAuth App** (one callback per app): callback
  `https://<app>.vercel.app/api/auth/github/callback`, then `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`.
- **Never set** `LANGSMITH_*` (traces would carry users' questions and page text) or `DEV_TOOLS`
  (lets any user reset their own daily limit).
- **Keep warm**: cron-job.org → `GET https://bookmark-brain-api.onrender.com/health` every 10 min.
  The free plan sleeps after 15 idle minutes, which would also pause the job worker (it runs inside
  the API process). 750 free hours a month cover one service running all the time.
- The worker fetches user URLs from Render's network; `app/services/fetch.py` blocks private and
  metadata addresses. Never bypass it.

## Vercel (frontend)
- Import the repo, root directory `frontend/`, framework Vite. `frontend/vercel.json` holds the
  `/api` forwarding (to the Render address; change it if Render gave the service another name) and
  the single-page-app fallback.
- Env: `VITE_GOOGLE_CLIENT_ID`. Leave `VITE_API_URL` unset (the API is on the app's own address).
- Google sign-in: add the Vercel address to the OAuth client's authorised JavaScript origins.

## Extension
- Before building: add `https://<app>.vercel.app/connect*` to `matches` in
  `extension/entrypoints/connect.content.ts` (one-click connect only works on matched pages), and the
  API host to `host_permissions` in `wxt.config.ts` if it isn't `*.onrender.com`.
- Build with `WXT_API_URL=https://<api>.onrender.com WXT_APP_URL=https://<app>.vercel.app npm run zip`.
- Bump `version` in `extension/package.json` for each store upload.
- Chrome Web Store as **unlisted** (one-time $5 developer fee), or share the zip for "Load unpacked".
- Firefox: `npm run zip:firefox` → addons.mozilla.org (free). Replace the placeholder gecko id
  `bookmark-brain@example.com` in `wxt.config.ts` with a real one first.
- Store listings need the 128 px icon (`extension/public/icon/128.png`) and a privacy note: the
  extension sends bookmark URLs, titles and folder names to the user's own account, nothing else.

## Rollback
Render: "Rollback" to a previous deploy. Vercel: promote a previous deployment. DB: write a new migration that reverses the change; don't run downgrade on prod with real data.
